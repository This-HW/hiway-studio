# ADR-0007: 타임라인 클립 목록은 `timeline_clips` 정규화 테이블에 저장

## 상태
승인 (HW가 2026-09-30에 승인)

## 배경
설계서 F-12는 타임라인의 클립 목록을 `clip_order` 배열(`{shot_id, video_id, in_sec, out_sec}`)로 기술한다.
그러나 저장소의 정본 문서(`docs/PROJECT_ARCHITECTURE.md` §4.1, `docs/MODULES.md`)는
`models/timeline.py`가 `timelines, timeline_clips` 두 테이블을 소유한다고 명시하며,
Phase 3 과업도 `timeline_clips` 테이블을 요구한다.
D-12(순서가 있는 목록은 JSONB 배열이 아니라 별도 테이블 — beats 선례)도 정규화 쪽을 지지한다.

## 결정 (제안)
- `timeline_clips`가 클립 목록의 유일한 저장 정본이다:
  `id, timeline_id(FK, CASCADE), position(INT, 타임라인 내 0-based 순서, UNIQUE(timeline_id, position)),
  shot_id(FK), video_id(FK), in_sec/out_sec(FLOAT, D-27), created_at`.
- `timelines.clip_order` JSON 컬럼은 두지 않는다(이중 정본 방지).
- API의 `clip_order`는 F-12 계약상 와이어 형태(wire shape)로 유지한다:
  조회 시 `timeline_clips`를 `position` 순으로 조립하고,
  `PATCH /timelines/{id}`의 `clip_order`는 기존 행을 전부 교체한다(원자적 replace).
- 렌더 워커는 같은 순서로 클립을 읽는다.

## 결과
- 순서 변경·트림·삭제가 행 단위 UPDATE/DELETE로 명확해지고, 렌더 중 409 잠금과도 자연히 맞아떨어진다.
- F-12의 `clip_order` API 계약은 그대로 유지되므로 설계서 §8.1 클라이언트와 충돌하지 않는다.
