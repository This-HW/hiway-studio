# ADR-0005: 마스터 초상 재생성 규칙

## 상태
승인 (HW가 2026-09-30에 승인)

## 배경
- `POST /characters/{id}/master`를 두 번 호출하면 두 번째 잡이 고정 경로
  `characters/{id}/master.png`에 쓰려고 시도한다.
- 설계서 §5·§6: "생성 완료된 파일은 불변(immutable). 덮어쓰기 금지, 재생성은
  새 파일 + 새 잡 행으로 기록한다."
- `character_references`에는 캐릭터당 primary 1개 부분 유니크 인덱스가 있다
  (design §4.7). 새 마스터가 항상 `is_primary=true`이므로 기존 primary와
  충돌한다.

고정 파일명·불변 산출물·primary 단일성을 동시에 만족하는 동작이 정의되지
않았다.

## 결정
1. 첫 마스터는 `master.png`에 저장한다 (안정된 대표 경로).
2. 마스터 재생성은 새 generation/job 행을 만들고, 출력 파일은
   `master_{generation_id 앞 8자리}.png`로 저장한다. 기존 파일을 덮어쓰지
   않는다.
3. 완료 시 새 `character_references` 행(`role='master'`)이
   `is_primary=true`가 되고, 기존 primary 행은 `is_primary=false`로
   강등된다. 이전 마스터 파일과 행은 히스토리로 유지되며 재생성이 삭제하지
   않는다.
4. 명시적 삭제(`DELETE /references/{id}`)는 여전히 가능하며, 이때 파일도
   함께 삭제된다 (사용자 주도 삭제는 불변 규칙의 예외).

## 근거
- "재생성은 새 파일 + 새 잡 행" 규칙을 그대로 따른다. `master.png`를 항상
  최신으로 덮어쓰는 대안은 불변 규칙을 깨뜨리므로 기각.
- primary 교체는 강등(demote) 방식으로 부분 유니크 인덱스를 만족한다.
  버전 번호를 올리는 대안은 참조 행이 이미 세대 구분 역할을 하므로 불필요.

## 영향
- 코드: `services/api/app/tasks/tasks_image.py::_save_character_image`
  (마스터 파일명 분기), `services/api/app/services/character_pipeline.py::reference_for_job`
  (기존 primary 강등).
- 문서: `docs/P0_SCREENS.md` 캐릭터 화면 § (재생성 문구 1줄),
  `docs/PROJECT_ARCHITECTURE.md` 변경 없음 (기존 불변 규칙의 구체화).
- 호환성: 기존 데이터와 API 응답 형태는 그대로. `master.png`는 첫 마스터의
  경로로 유지된다.

## 관련
- 시스템 설계서 §5 (불변 산출물), §4.7 (character_references),
  §8.1 `POST /characters/{id}/master`.
