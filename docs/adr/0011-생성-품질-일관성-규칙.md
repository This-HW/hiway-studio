# ADR-0011: 생성 품질·일관성 규칙 — 프롬프트 템플릿·레퍼런스·시드·멀티패스

## 상태
승인 (HW가 2026-10-04에 "검증된 방법이면 스펙에 바로 반영" 지시 — 2026-10-05 전수검수에서 확정)

## 배경
실 ComfyUI(SD 1.5) 검증(2026-10-02~03)에서 파이프라인은 동작하지만 출력물이
"중구난방"이다: 캐릭터 외형이 샷마다 바뀌고(시트 정면이 마스터와 다른 인물로
나옴), 프롬프트 디테일이 부족하다. 원인은 프롬프트에 고정 틀이 없고, 캐릭터
레퍼런스가 프롬프트 텍스트에만 의존하며, 시드가 매번 랜덤이기 때문이다.
2026-10-03 리서치(artifacts ai-4, `research_notes/ai-studio-quality-research-20261003-1524/`)
에서 Midjourney 공식 가이드·Higgsfield·Runway/Sora·SD 커뮤니티의 검증된
기법을 확인했다. 학습(LoRA/DreamBooth)은 범위 밖 — 학습 없이 되는 것만 채택한다.

## 결정

### 1. 고정 프롬프트 슬롯 순서 (설계서 §7.1 개정)
조립 순서를 `주제 → 배경 → 스타일/매체 → 조명 → 카메라/렌즈 → 색감/분위기 → 파라미터`
로 고정한다. 앞쪽 토큰이 강하게 먹으므로 주제는 5~8단어로 맨 앞에 둔다.
모순되는 스타일 2개 이상을 한 프롬프트에 넣지 않는다 (평균화되어 뭉개짐).

### 2. 모델별 토큰 예산 + 가중치 문법
SD 1.5 CLIP 인코더는 77토큰 하드캡 — 초과분은 조용히 잘린다. 프롬프트는
밀도 있게, 품질 부스터는 앞에 둔다. 가중치 문법 `(단어:1.3)`·`((단어))`·
`[약화]`를 지원한다. 토큰 정책은 `constraints`에 모델별로 둔다 (하드코딩 금지 —
기존 불변식 유지).

### 3. 네거티브 프롬프트 라이브러리
품질/신체/텍스트/구도 4세트의 짧고 타겟팅된 기본 세트를 제공한다
(`blurry, low quality, bad anatomy, extra limbs, text, watermark, ...`).
거대한 복사-붙여넣기 네거티브는 모델과 싸워서 오히려 해가 되므로 금지.
보관함은 `prompt_snippets` (P1-8)를 사용한다.

### 4. 캐릭터 정체성 규칙 — "얼굴은 다시 묘사하지 마라"
캐릭터마다 canonical 레퍼런스 이미지 + 외형 고정 문구(identity clause:
헤어·의상·특징점)를 둔다. 씬 프롬프트에서는 얼굴·핵심 외형을 재묘사하지
않는다 — 정체성은 레퍼런스가 잡고 프롬프트는 바뀌는 것(의상·장소·행동)만
묘사한다 (Higgsfield Soul ID·InstantID·Runway I2V 공통 규칙).
재묘사는 드리프트를 유발한다.

### 5. 레퍼런스 컨디셔닝 (학습 없이)
IP-Adapter / IP-Adapter-FaceID / InstantID를 ComfyUI provider 시드에
수용한다 (가중치 0.6~1.0, 레퍼런스 5~10장 권장). 학습이 필요 없고 기존
모델을 그대로 쓴다. 단, 우리 환경에서의 노드 호환성은 미검증이므로
구현 시 실검증이 선행 조건이다 (리서치 caveat).

### 6. 시드 규율 — 배치 → 선택 → 고정 → 반복
탐색은 랜덤 시드 배치로, 마음에 드는 것을 고르면 시드를 고정하고
프롬프트만 다듬는다. 같은 시퀀스 내 샷들은 동일 시드를 공유한다.
`shot.seed` 명시 > 핀된 시드 재사용 > 호출별 랜덤 순 (P1-3 기존 규칙 유지).

### 7. 키프레임-퍼스트 영상 파이프라인
영상은 스틸 키프레임을 먼저 생성·승인하고, I2V 프롬프트는 **모션만**
묘사한다 (피사체·구도·색감 재묘사 금지 — Runway/Sora 공식 규칙).
재묘사는 모션을 죽이고 샷을 불안정하게 만든다.

### 8. 카메라 무브 enum
자유 텍스트 카메라 묘사를 금지하고 명명된 무브 enum에서 선택한다
(`contracts/enums.json`의 `camera_movement`, 22종: static·pan·tilt·dolly in/out·
truck·crane·jib up/down·orbit·orbit_360·zoom in/out·crash zoom in/out·
dolly zoom in/out·whip pan·snorricam·hyperlapse·handheld·fpv).
한 클립당 1무브·1액션·1조명 규칙. 긴 클립은 timed beats
(5초=2비트, 10초=3~4비트).

### 9. 연속성 앵커 체크리스트
멀티샷 연속 생성 시 매 샷마다 5개 앵커를 명시한다: 정체성·의상·이동 방향·
카메라 거동·환경 마커 2개. 조명·팔레트 토큰은 샷마다 verbatim 반복.
last-frame 체인은 기존 `continuity.py` 폴백 체인을 그대로 쓴다.
확장 체인이 길어지면 원본 클립에서 re-seed (드리프트 누적 방지).
클립 꼬리 8~12프레임은 트림한다 (모델이 ease-out으로 마무리함).

### 10. 멀티패스 — 승인된 후보에만 후처리
hires-fix (2nd pass, denoise 0.4, 1.5×) + 얼굴 복원 (ADetailer/CodeFormer,
GFPGAN→Real-ESRGAN 순서)을 승인된 후보에만 적용한다. 미승인 후보에
후처리를 돌리지 않는다 (비용 낭비).

### 11. 수정은 인페인팅으로, reroll이 아니다
마음에 드는 부분은 살리고 고칠 곳만 작은 마스크로 인페인팅한다
(한 번에 한 영역). 요소 추가 시 `(요소:1.2)`를 프롬프트 맨 앞에 둔다.

### 12. 재생성 규율 — 한 번에 하나의 변수만
"고치고 싶은 X만 바꾸고 나머지는 전부 유지" (Higgsfield edit 공식).
한 번의 재생성에서 프롬프트·시드·모델 중 하나만 바꾼다.

### 13. 프로젝트 스타일 바이블
프로젝트마다 팔레트·조명·렌즈·그레이드 고정 토큰을 `style_kit` 잠금과
연동해 모든 프롬프트에 주입한다 (스타일킷 P0의 구체화).
`is_locked` 키트는 프롬프트 조립 시 verbatim 주입된다.
**스타일 권위는 프로젝트당 하나** (Higgsfield Cinema Studio 방식):
잠긴 키트가 있으면 샷 단위 스타일 재정의는 불가하다 — Manual Style이
프리셋 축을 "대체"하듯, 잠금과 샷 재정의는 동시에 쓸 수 없다.
다른 룩이 필요하면 `POST /style-kits/{id}/duplicate`로 새 버전을 만들어(잠금 해제 아님 — 잠긴 키트는 직접 수정 불가) 재정의한다.
이렇게 해야 스타일 바이블이 무력화되지 않는다.

### 14. GenerationSnapshot — 재현성
모든 generation에 모델/시드/샘플러/CFG/스타일 토큰/네거티브/레퍼런스 ID를
스냅샷으로 저장한다. 같은 스냅샷이면 같은 결과가 나와야 한다
(결정적 provider + 고정 시드 전제).

## 근거
- 버린 대안: 자유 형식 프롬프트 유지 — "중구난방"의 직접 원인이라 기각.
- 버린 대안: LoRA/DreamBooth 학습 — 효과는 가장 강하지만 학습 파이프라인이
  범위 밖. IP-Adapter/InstantID로 80%를 먼저 확보한다.
- 출처: Midjourney 공식 프롬프트 가이드, Higgsfield camera-controls·Soul ID
  커뮤니티 스킬, Runway Gen-4.5·Sora I2V 가이드, SD 커뮤니티
  (portkey·lora-pilot), diffusers 시드 문서. 전문은 리서치 페이지(artifact ai-4).
